# Telegram Pipeline Requirements

1) 기능 요구사항 (Functional)

R1. 채널 메시지 수집
  - 등록된 텔레그램 채널 목록에서 신규 메시지를 주기적으로 수집한다.
  - 텍스트 기반 메시지만 처리하며, 미디어 전용 메시지는 무시한다.
  - 수집 대상 채널 목록 및 인증 정보는 환경 변수로 관리하고 코드 하드코딩을 금지한다. 구체적인 키 이름·권한 부여 절차는 운영 매뉴얼에서 관리한다.

R2. 메시지 정규화 및 지능형 필터링 (확장)
  - 비정형 텍스트에서 발신 채널, 시각, 핵심 텍스트, 추출 키워드를 분리하여 정규화된 딕셔너리(telegram_message_dict)로 변환한다.
  - [종목 필터링 및 밸류체인 맵핑]:
    - 국내 종목: 메시지 내 종목명/코드 인식 시 즉시 수집하여 해당 종목 분석의 Reference로 활용할 수 있도록 식별자를 추출한다.
    - 해외 종목: 수집 대상을 '국내 산업과 밀접한 글로벌 리더'(예: NVDA, TSMC, AAPL, TSLA 등)로 제한한다. 해외 종목 포착 시 AI를 통해 국내 3대 밸류체인(공급망/경쟁사/전방산업) 연관 종목을 맵핑한다.
  - [시황 수집 및 전이 분석]:
    - 국내 시황: 당일 수급(기관/외인), 섹터 로테이션, 정책 이슈를 우선적으로 추출한다.
    - 해외 시황: 국내 시장에 영향을 미치는 '매크로 트리거' 추출에 집중하며, 해당 현상이 내일 한국 증시의 환율, 금리, 특정 섹터 수급을 어떻게 자극할 것인가에 대한 "전이 경로(Transmission Path)"를 3문장 이내로 추론하여 포함한다.
  - 정규화/분석 실패 메시지는 결과 리스트에서 제외(스킵)하고 로그만 남긴다.

R3. 책임 한정 (관심사 분리)
  - 본 파이프라인은 수집/정제/분석 + 반환까지만 담당한다.
  - Market Chronicles 인덱스 적재, AI 프롬프트 주입 등 후속 동작은 본 파이프라인이 직접 호출하지 않는다(오케스트레이터가 위임 라우팅).
  - src/memory/, src/strategy/ 등 후속 도메인 모듈을 import 하지 않는다.
  - [예외] 정규화 보조용 상태 비저장(stateless) AI 헬퍼(ai_logic.analyze_value_chain, ai_logic.extract_transmission_path)는 호출 가능하다. 단, 해당 헬퍼는 외부 상태를 변경하지 않고 결과 dict 만 반환해야 하며, 도메인 의사결정(매수/적재) 로직을 포함해서는 안 된다.

R4. 중복 방지
  - 채널별 마지막 처리 메시지 식별자를 영속화하여 시스템 재기동 후에도 중복 수집을 방지한다(영속화 키 구조는 03 상태로직 참조).

2) 비기능 요구사항 (Non-Functional)

N1. 에러 격리 (A-Type 기본)
  - Rate Limit / 네트워크 일시 장애 / 단일 메시지 파싱(또는 AI 전이 분석) 실패는 A-Type 으로 처리.
  - 외부 장애로 인해 트레이딩 코어(KIS 주문, 리스크 감시) 흐름이 중단되어서는 안 된다.
  - 본 파이프라인은 어떠한 예외도 호출자에게 전파하지 않으며, 항상 결과 리스트를 반환한다.

N2. 운영자 개입 신호 (B-Type 위임)
  - 인증 정보 누락/잘못 구성 등 자가복구 불가 케이스는 오케스트레이터가 B-Type 으로 처리하도록 신호(예: 결과 dict 의 메타 필드)만 노출한다. Pause 결정 자체는 본 파이프라인이 내리지 않는다.

N3. 토큰 효율
  - 정제 결과의 핵심 텍스트는 후속 AI 호출 비용을 고려하여 길이 상한을 둔다.
  - 전이 분석 시 최소한의 컨텍스트만 주입하여 AI 토큰 낭비를 방지한다. 원문 보존이 필요한 경우 보조 필드에 분리 저장한다.

3) 운영 제약
  - 텔레그램 인증 정보 및 채널 목록은 환경 변수로만 주입(.env 직접 읽기 금지).
  - 해외 핵심 종목(글로벌 리더) 리스트는 환경 변수 또는 별도 설정 파일로 분리 관리한다.
  - 외부 도메인(Market Chronicles 등)으로의 직접 import 금지.
